# GEMINI.md

## Project Overview

This is a digital queue system featuring a monorepo structure. The backend is a Go-based microservice (`http-service`) responsible for user authentication and management. It uses a PostgreSQL database for data storage. An API gateway is implemented using Kong, which acts as the single entry point for all incoming API requests, handling routing and authentication. The project is containerized using Docker, and Make is used for simplifying development setup and workflows.

## Building and Running

The project uses Docker Compose and a `Makefile` to orchestrate the development environment.

**Key Commands:**

*   **Start all services:**
    ```bash
    make compose-up
    ```
*   **Stop all services:**
    ```bash
    make compose-down
    ```
*   **View service logs:**
    ```bash
    make compose-logs
    ```
*   **List running services:**
    ```bash
    make compose-ps
    ```
*   **Rebuild and start all services:**
    ```bash
    make compose-rebuild
    ```
*   **Sync Kong configuration:**
    ```bash
    make kong-sync
    ```

## Development Conventions

### Backend

*   The backend is written in Go and follows a standard project layout, separating concerns into `cmd`, `internal`, and `pkg` directories.
*   The `http-service` uses the Gin web framework.
*   Database migrations are used to manage the PostgreSQL schema.
*   User authentication is handled via JWTs.
*   The `zerolog` library is used for logging.

### API

*   The API is documented using the OpenAPI specification in `api/auth-service.yaml`.
*   The Kong API Gateway is used to manage and expose the API.

### Database

*   The project uses PostgreSQL as its database.
*   The database schema includes tables for users, organizations, roles, and permissions, indicating a role-based access control (RBAC) system.
